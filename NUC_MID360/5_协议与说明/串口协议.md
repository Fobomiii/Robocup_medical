# NUC 与 STM32 Nav2 串口协议

串口参数：`115200 8N1`，NUC 默认设备 `/dev/ttyUSB0`。串口只能由
`stm32_bridge` 一个 ROS 节点打开。

## 1. 握手

```text
STM32 -> NUC: A5 5A 01 00
NUC   -> STM32: A5 5A 01 01
```

## 2. 通用帧

```text
AA CC  VER TYPE SEQ LEN  PAYLOAD...  CRC_H CRC_L
```

- `VER=1`，`LEN<=48`。
- 多字节字段均为大端序。
- CRC 为 CRC16-CCITT-FALSE，初值 `0xFFFF`、多项式 `0x1021`，计算范围为
  `VER` 到 `PAYLOAD` 末尾。

## 3. STM32 到 NUC

| TYPE | 名称 | PAYLOAD |
|---|---|---|
| `0x10` | `POSE` | `x_mm:i32, y_mm:i32, yaw_cdeg:i16, task:u8, nav_status:u8, path_id:u16, waypoint_index:u8` |
| `0x11` | `GOAL_REQUEST` | `request_id:u16, goal_id:u8` |
| `0x13` | `STP23L` | `a_mm:u16, b_mm:u16, c_mm:u16, valid_mask:u8` |
| `0x14` | `SCAN_ACK` | `scan_id:u16, status:u8` |
| `0x15` | `WHEEL_ODOM` | `forward_mm_s:i16, left_mm_s:i16, yaw_ccw_cdeg_s:i16, online_mask:u8, stamp_cs:u16` |
| `0x16` | `TTS_REQUEST` | `request_id:u16, bed:u8` |
| `0x17` | `WHEEL_DIAGNOSTICS` | `target_rpm:i16[4], measured_rpm:i16[4], command_current:i16[4], feedback_current:i16[4], online_mask:u8, current_saturation_mask:u8, stamp_cs:u16` |

`POSE` 每 20 ms（50 Hz）发送一次，格式保持不变：X/Y 只能来自 OPS9，航向只能来自 HWT101CT。
`WHEEL_ODOM` 同样每 20 ms（50 Hz）发送一次，速度来自四个 M3508/C620 的编码器转速：

- `forward_mm_s > 0` 为车体向前，`left_mm_s > 0` 为车体向左，
  `yaw_ccw_cdeg_s > 0` 为逆时针旋转。
- `online_mask` bit0~bit3 分别对应 CAN ID 1~4，`0x0F` 表示四轮反馈均在线；
  任一位缺失时 NUC 不采用该帧做 EKF 轮速更新。
- `stamp_cs` 是 STM32 启动后的百分之一秒计数，16 位循环，NUC 按回绕方式计算周期。
- C620 转子 RPM 先除以 `19:1` 减速比，再用 `152 mm` 轮径和现有四轮混控矩阵反解车体速度。

`WHEEL_DIAGNOSTICS` 每 50 ms（20 Hz）发送一次，不参与控制与 EKF，仅用于定位高速斜行时的轮速失配。四轮顺序为前、左、后、右；电流字段均为 C620 原始值。NUC 将其发布到 `/medical_nav/wheel_diagnostics`，其中同时计算 `rpm_error = target_rpm - measured_rpm`。

`stm32_bridge` 在每次处理安全速度时同步发布纯诊断话题
`/medical_nav/bridge_cmd_debug`。JSON 中的 `safe_cmd` 是 Collision Monitor
输出，`release_limited_cmd` 是常驻非对称轮面加速度限制后的结果，`sent_cmd`
是经过 X-drive 合速度、轮面速度和航向限制后实际编码给 STM32 的速度。
限速器对停车和减速立即放行，对任意重新增速按轮面加速度上限恢复；
`gate_release.mode=continuous_asymmetric`，`limiting` 表示当前正在限制增速。
该诊断话题不参与控制。

NUC 以轮速进行运动预测，位置 X/Y 仍由轮速与 OPS 位置滤波；航向不再进入 EKF 融合，直接采用
`POSE` 中的 HWT101CT yaw，融合结果继续发布到
原有 `/odom` 与 `odom -> base_link`。原始轮速发布到 `/medical_nav/wheel_odom`；若轮速超过
`0.15 s` 未更新或四轮未全部在线，则自动退回原有 OPS/HWT 位姿输出，兼容旧 STM32 固件。
`STP23L` 每 100 ms（10 Hz）发送一次：A=右、B=前、C=左，距离为传感器表面到目标的
原始毫米数。`valid_mask` bit0/1/2 分别表示 A/B/C 在线且数据新鲜。

场地坐标：`+X 向右、+Y 向前、yaw 顺时针为正`。NUC 转换为：

```text
ros_x = y_mm / 1000
ros_y = -x_mm / 1000
ros_yaw = -yaw_cdeg / 100 deg
```

目标编号：`1=home`、`2=nurse`、`3=bed1`、`4=bed3`。

## 4. NUC 到 STM32

| TYPE | 名称 | PAYLOAD |
|---|---|---|
| `0x12` | `NAV_STATUS` | `request_id:u16, goal_id:u8, status:u8` |
| `0x30` | `HEARTBEAT` | `counter:u32` |
| `0x40` | `VEL_CMD` | `forward_mm_s:i16, left_mm_s:i16, yaw_ccw_cdeg_s:i16, stamp_cs:u16` |
| `0x41` | `SCAN_RESULT` | `scan_id:u16, context:u8, format:u8, length:u8, value:ASCII[length]` |
| `0x42` | `TTS_STATUS` | `request_id:u16, status:u8` |

`TTS_REQUEST` 仅允许 `bed=1/3`。STM32 在药盒舵机打开 1 秒后每
`250 ms` 重发同一个请求；NUC 使用 `ffmpeg` 解码预先合成的
`/home/fzurobot/Downloads/1_.mp3` 或 `3_.mp3`，并由 ALSA 播放，
播放在线程中进行，不阻塞 ROS、串口或底盘速度链。`TTS_STATUS` 的
`status=1` 表示播放完成，`status=2` 表示播放失败。STM32 只有在床位条码
确认且收到播放完成状态后才离开；通信或音频故障超过 10 秒时执行防死锁降级。

`POSE.task_state` 现在由 STM32 的医疗任务适配层填写：

| 值 | 状态 |
|---:|---|
| 0 | 初始化 |
| 1 | Nav2 前往护士台 |
| 2 | 扫描护士台任务码 |
| 3 / 6 | Nav2 前往 1 / 3 号床 |
| 4 / 7 | 扫描 1 / 3 号床床头码 |
| 5 / 8 | 1 / 3 号床放药 |
| 9 | Nav2 返回起点 |
| 10 | 任务完成 |
| 11 | Nav2 导航错误，任务停止 |

该状态机不执行 STM32 本地寻点、旧 OA 或分段航点跟随；所有移动均由
`GOAL_REQUEST` 对应的 Nav2 `NavigateToPose` 完成。

`VEL_CMD` 使用 ROS 车体符号：

- `forward_mm_s > 0`：向前。
- `left_mm_s > 0`：向左平移。
- `yaw_ccw_cdeg_s > 0`：逆时针旋转。
- `stamp_cs`：NUC 启动后的百分之一秒计数，16 位循环。

STM32 将速度换算为四轮 RPM：

```text
wheel_rpm = linear_mm_s * 60 / (pi * 152)
turn_mm_s = yaw_rad_s * 250
```

其中 `250 mm` 是当前实测旋转等效半径；Nav2 车体物理半径为 `225 mm`。

导航状态：`0=IDLE`、`1=WAIT_PATH`、`2=FOLLOWING`、`3=REACHED`、`4=ERROR`。

## 5. STP23L 床位标定

- 三个模块距车体中心半径均为 `153 mm`。
- 1 床使用 B（前）+C（左）；3 床使用 B（前）+A（右）。
- 停车圆半径为 `300 mm`，圆边与床的内侧边相切；床头柜与床紧贴，柜前缘为
  `y=5900 mm`。
- 侧向传感器光路不受床遮挡，使用外侧场地边界作为绝对参考。停车圆心到外侧边界
  为 `1300 mm`，因此侧向 STP 原始读数应约 `1300-153=1147 mm`；前向原始读数
  应约 `500-153=347 mm`。
- ROS 只在 1/3 床任务状态、低航向偏差、距离符合已知几何且连续多帧稳定时更新
  OPS XY 偏置；其他位置、人或随机障碍物遮挡时不标定。
- 原始 OPS 位姿保留在 `/medical_nav/ops_raw_pose`，校正后位姿用于 `/odom`和
  `/medical_nav/robot_pose`。标定状态为 `/medical_nav/ops_calibration`。

## 6. NUC 相机扫码

DECXIN 相机节点只在任务态 `2/4/7` 解码，避免行驶途中看到其他码后提前触发任务：

| 任务态 | context | format | 允许值 |
|---:|---:|---:|---|
| 2（护士台） | 1 | 1（QR） | `11`、`13`、`31`、`33` |
| 4（1 号床） | 2 | 2（CODE128） | 赛事提供的 6 个床头条形码之一 |
| 7（3 号床） | 3 | 2（CODE128） | 赛事提供的 6 个床头条形码之一 |

相机端连续两次识别一致后发送 `SCAN_RESULT`。NUC 每 `150 ms` 重发同一个 `scan_id`，
直到收到 STM32 的 `SCAN_ACK`，或 STM32 上报的任务态已经离开对应扫码状态。STM32 会再次
检查当前任务态、context、format 和白名单，然后才允许状态机继续。ACK 状态为
`1=ACCEPTED`、`2=WRONG_STATE`、`3=INVALID_CODE`。GM65 仍作为独立备用扫码器，沿用连续
四次一致确认。

## 7. 安全策略

- STM32 连续 `600 ms` 未收到合法 `VEL_CMD`，进入底盘减速斜坡；OPS/HWT 或轮子反馈失效时使用独立立即停车。
- OPS9 或 HWT101CT 任一掉线，STM32 不执行速度并下发零速。
- 只有任务态 `1/3/6/9` 且导航态为 `FOLLOWING` 时才允许执行速度；NUC 和 STM32
  各自独立检查，扫码、放药、完成和错误状态一律零速。
- NUC 在安全速度话题停止更新时主动发送零速；STM32 超时是第二道独立保护。
- Collision Monitor 输入 `/cmd_vel`，输出 `/cmd_vel_safe`；`stm32_bridge` 只订阅后者。
- bridge 直接启动和首次/重新部署均默认 `dry_run=true`，必须人工检查后解锁。
- 旧的 `0x20–0x23` 路径帧和 `AA BB ... 55` 障碍帧解析代码为迁移兼容保留，
  当前 Nav2 启动链不再发送，也不再驱动底盘。
